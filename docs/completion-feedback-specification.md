## 한 줄 결정

Canvas 이미지 합성이 성공한 직후 완성 모달 상단에 `체크 배지 + 완료 문구`를 즉시 표시하고, 체크 배지만 700ms 이내로 한 번 애니메이션합니다. 미리보기·합성 중·이미지 생성 완료·기기 저장 상태는 서로 다른 문구로 구분합니다.

## 배경과 문제

현재 사용자는 미리보기에서 `일기 완성하기`를 누르고 이미지 합성이 끝나면 완성 모달로 이동합니다. 모달에는 `그림일기가 완성됐어요`라는 정적 제목이 있지만, 다음 이유로 완료 여부가 충분히 분명하지 않을 수 있습니다.

- 실제 합성 전인 미리보기 진행 표시가 이미 `3/3 그림일기 완성`이라고 안내합니다.
- 합성 중에도 버튼 문구가 `일기 완성하기`로 유지되고 별도 진행 문구가 없습니다.
- 합성 성공 후에는 정적 제목만 추가되어 미리보기와 상태 차이가 약합니다.
- 그림일기 이미지가 준비된 상태와 기기에 저장된 상태가 분리되어 있지만, 사용자가 둘을 같은 완료로 이해할 수 있습니다.

이 명세에서 `그림일기 완성`은 `composeDiaryImage()`가 성공해 JPEG data URL이 준비된 상태를 뜻합니다. `이미지 저장`은 완성 모달에서 사용자가 별도로 실행하는 후속 동작입니다.

## 목표

- 합성 성공 후 1초 안에 그림일기가 완성되었음을 알아볼 수 있게 합니다.
- 움직임을 보지 못해도 아이콘과 문구만으로 같은 상태를 이해할 수 있게 합니다.
- 그림일기가 완성되었지만 아직 기기에 저장되지는 않았음을 구분합니다.
- 기존 저장·공유·계속 보기·새 일기 쓰기 흐름을 방해하지 않습니다.

## 범위

### 필수 범위

- 미리보기 단계 문구 정리
- 합성 중 버튼 상태 표시
- 완성 모달 상단의 체크 배지와 완료 문구
- 1회성 성공 애니메이션
- 모션 감소 설정, 스크린 리더, 작은 화면 대응
- 기존 합성 실패와 재시도 흐름 유지

### 제외 범위

- 자동 저장 또는 자동 공유
- 음향, 진동, 햅틱
- 전체 화면 폭죽·종이 조각 효과
- 반복 또는 상시 재생 애니메이션
- 완성 이미지 자체의 확대·회전
- 일기 미리보기와 저장·공유 모달 전체 재설계
- 실제 공유 완료 여부 판정

## 화면 명세

완성 모달의 기존 제목 블록을 다음 성공 헤더로 교체합니다. 별도의 큰 영역을 추가하지 않고 기존 헤더 안에 통합해 완성 이미지와 하단 버튼 공간을 유지합니다.

```text
┌──────────────────────────────────┐
│  [ ✓ ]  그림일기가 완성됐어요!   │
│         완성 이미지를 만들었어요. │
│         기기에 보관하려면         │
│         ‘이미지 저장하기’를       │
│         눌러주세요.               │
│                                  │
│        [완성 이미지 미리보기]     │
│                                  │
│  [이미지 저장하기]               │
│  [앱 공유하기]                    │
│     계속 보기 | 새 일기 쓰기      │
└──────────────────────────────────┘
```

### 표시 요소

| 요소      | 명세                                                                          |
| --------- | ----------------------------------------------------------------------------- |
| 체크 배지 | 56×56px 권장, 원형 또는 손도장 느낌. 연한 완료색 배경과 진한 체크를 사용      |
| 제목      | `그림일기가 완성됐어요!`                                                      |
| 설명      | `완성 이미지를 만들었어요. 기기에 보관하려면 ‘이미지 저장하기’를 눌러주세요.` |
| 미리보기  | 현재 완성 이미지와 `완성된 그림일기` 대체 텍스트 유지                         |
| 저장 안내 | 현재 `이미지 저장 시 기기의 저장 화면이 열릴 수 있어요.` 유지                 |

체크 배지는 완료 상태 전용 자산 또는 inline SVG를 사용합니다. 평가 결과인 `great.png` 도장과 비속어 첨삭에 쓰는 `check1.png`, `check2.png`는 의미가 다르므로 재사용하지 않습니다.

### 색상과 대비

- 기존 완료 진행점의 `#78bda1` 계열을 배지 배경 또는 테두리에 활용할 수 있습니다.
- 체크 전경색은 배경과 3:1 이상, 문구는 배경과 4.5:1 이상 대비를 확보합니다.
- 성공 여부를 녹색만으로 표현하지 않고 체크 형태와 `완성됐어요` 문구를 항상 함께 표시합니다.

### 반응형

- 성공 헤더는 배지와 문구를 가로로 배치하고, 문구 영역에는 `min-width: 0`을 적용합니다.
- 너비 359px 이하 또는 높이 600px 이하에서는 배지를 44×44px로 축소하고 간격을 줄입니다.
- 완료 헤더 때문에 완성 이미지의 현재 최소 높이 80px이나 하단의 네 액션이 잘리면 안 됩니다.
- 텍스트 확대와 줄바꿈에도 가로 스크롤이 생기지 않아야 합니다.

## 애니메이션 명세

완료 문구와 모든 액션은 모달 첫 프레임부터 최종 상태로 표시합니다. 애니메이션은 추가 강조일 뿐이며 정보나 조작을 늦추지 않습니다.

| 구간       | 대상                         | 효과                                                               |
| ---------- | ---------------------------- | ------------------------------------------------------------------ |
| 0ms        | 완료 헤더                    | 제목과 설명을 즉시 표시                                            |
| 80~560ms   | 체크 배지                    | `opacity: 0 → 1`, `scale: 0.84 → 1.06 → 1`, `rotate: -4deg → 0deg` |
| 260~700ms  | 작은 별 또는 햇살 장식 2~3개 | `opacity`와 `scale`로 한 번 나타난 뒤 700ms까지 사라짐             |
| 700ms 이내 | 전체 효과                    | 모든 움직임 종료                                                   |

- 기존 도장 등장 모션과 비슷한 탄성 easing을 사용합니다.
- `transform`과 `opacity`만 움직여 레이아웃 이동과 WebView 렌더링 부담을 피합니다.
- 애니메이션 도중에도 저장·공유·계속 보기·새 일기 쓰기를 바로 누를 수 있어야 합니다.
- 장식 레이어에는 `pointer-events: none`을 적용합니다.
- 한 번 생성된 완성 이미지마다 모달 최초 진입 시 한 번만 재생합니다.
- 저장·공유의 pending·성공·실패 상태 변경이나 재시도로 완료 모션을 다시 재생하지 않습니다.
- 모달을 닫고 다시 `일기 완성하기`를 눌러 새 완성 이미지를 생성했다면 새 결과로 보고 한 번 재생할 수 있습니다.

### 모션 감소

`prefers-reduced-motion: reduce`에서는 배지와 장식의 애니메이션을 모두 제거하고 최종 체크 배지와 완료 문구를 즉시 표시합니다. 정보량과 액션은 일반 모드와 같아야 합니다.

## 동작 명세

### 미리보기

- `STEP_PROGRESS.preview.label`을 `그림일기 완성`에서 `마지막 확인`으로 변경합니다.
- 합성 시작 시 `일기 완성하기` 버튼 문구를 `완성 중…`으로 바꿉니다.
- 합성 중 버튼은 `disabled`와 `aria-busy="true"`를 함께 사용해 중복 요청을 막습니다.
- 합성 실패 시 성공 배지나 완성 모달을 표시하지 않습니다.

### 완성 모달

- `finishedDiary`가 `null`에서 완성 결과로 바뀌어 모달이 열릴 때 성공 상태를 표시합니다.
- 모달은 성공 애니메이션이 끝나도 자동으로 닫히지 않습니다.
- `계속 보기`는 현재처럼 완성 모달만 닫고 미리보기를 유지합니다.
- `새 일기 쓰기`는 현재처럼 완성 결과와 draft를 초기화하고 업로드로 이동합니다.
- 저장·공유 오류가 발생해도 성공 헤더와 완성 이미지는 유지합니다.

## 접근성

- 모달이 열릴 때 TDS `Modal.Content`의 `onOpenAutoFocus`에서 기본 포커스를 막고 완료 제목으로 포커스를 이동합니다.
- 완료 제목은 `h2`, `tabIndex={-1}`로 제공하고 설명과 함께 dialog의 이름과 설명으로 연결합니다.
- 스크린 리더는 최초 진입 시 `그림일기가 완성됐어요. 완성 이미지를 만들었어요. 기기에 보관하려면 이미지 저장하기를 눌러주세요.`를 한 번만 읽어야 합니다.
- 체크 아이콘과 별·햇살 장식은 `aria-hidden="true"`로 처리합니다.
- 성공 알림에 `role="alert"`를 사용하지 않습니다. 제목 포커스로 한 번 안내하고 중복 live announcement를 만들지 않습니다.
- 애니메이션이 끝날 때 포커스를 다시 이동하지 않습니다.
- 저장·공유 오류의 기존 `role="alert"`는 유지합니다.
- 키보드 포커스 트랩과 모달 닫기 후 포커스 복귀는 TDS Modal의 기존 동작을 유지합니다.

## 후속 개선 제안

이미지 저장 결과 안내는 이 완료 효과와 별도 상태로 추가하는 것이 좋습니다. 브라우저에서는 실제 파일 저장 완료를 확인할 수 없으므로 `다운로드를 시작했어요`, Toss 저장 API가 정상 반환하면 `이미지 저장 요청을 완료했어요`처럼 확인 가능한 사실만 안내합니다. 공유는 현재 사용자 취소와 성공을 구분하지 않으므로 서비스 반환 형식을 확장하기 전에는 `공유 완료`라고 표시하지 않습니다.
