## 범위와 상태 기준

이 문서는 현재 저장소의 React 실행 경로를 기준으로 사용자가 조작할 수 있는 기능을 명세합니다.

- `구현 완료`: UI부터 결과 또는 오류 처리까지 실행 경로가 있음
- `부분 구현`: 핵심 흐름 일부만 있거나 저장소 밖 구성에 의존함
- `확인 필요`: 저장소 코드만으로 상태를 확정할 수 없음

주 Actor는 로그인 없이 미니앱 또는 모바일 브라우저를 사용하는 `사용자`입니다. 별도의 관리자·회원 역할은 없습니다.

## F-01 온보딩 시작

- **목적:** 제품 이름과 여름 테마를 보여주고 제작 흐름에 진입시킵니다.
- **Actor:** 사용자
- **사전 조건:** 앱이 로드됨
- **입력:** `시작하기` 버튼 탭
- **정상 흐름:** 온보딩을 닫고 사진 업로드 1단계로 이동합니다.
- **예외 흐름:** 없음
- **출력:** 업로드 화면
- **권한:** 없음
- **관련 화면:** 온보딩, 업로드
- **관련 API:** 앱 로드 시 `quota-status`를 비차감 조회할 수 있음(F-10)
- **관련 데이터:** 온보딩 표시 여부는 React 메모리 상태이며 영구 저장하지 않음
- **완료 조건:** 업로드 화면과 1/3 진행 상태가 표시됨
- **상태:** `구현 완료`
- **근거:** `src/App.tsx`, `src/hooks/useAiQuota.ts`

## F-02 사진 처리 동의

- **목적:** 사진·일기와 남용 방지용 식별 정보의 처리 범위를 사진 선택 전에 알립니다.
- **Actor:** 사용자
- **사전 조건:** 아직 사진을 선택하지 않은 업로드 화면
- **입력:** `여름 사진 올리기`, 필수 체크박스, `동의하고 사진 선택`
- **정상 흐름:** 동의 내용을 확인하고 체크한 뒤 운영체제 파일 선택기를 엽니다.
- **예외 흐름:** 체크하지 않고 진행하면 체크 영역으로 이동하고 토스트를 표시합니다. 닫으면 사진 선택이 시작되지 않습니다.
- **출력:** 파일 선택기
- **권한:** Granite 권한 없음. HTML 파일 입력을 사용합니다.
- **관련 화면:** 업로드 화면의 `사진·일기 처리 동의` 모달
- **관련 API:** 없음
- **관련 데이터:** 동의 체크 상태는 모달 메모리 상태만 사용하며 별도 동의 이력을 저장하지 않음
- **완료 조건:** 동의 후 파일 선택기가 열림
- **상태:** `구현 완료`
- **근거:** `src/components/PhotoUploadStep.tsx`, `granite.config.ts`

## F-03 사진 선택·검증·자르기

- **목적:** 그림일기에 사용할 사진 한 장을 유효한 크기와 고정 비율로 준비합니다.
- **Actor:** 사용자
- **사전 조건:** 최초 선택은 F-02 동의 완료, 교체는 기존 사진 존재
- **입력:** JPEG/JPG·PNG·WEBP 파일 1장, 자르기 위치, 1~3배 확대값
- **정상 흐름:**
  1. MIME과 10MB 제한을 검사합니다.
  2. 이미지를 디코딩하고 가로·세로가 각각 200px 이상인지 검사합니다.
  3. 사용자가 3:2 영역을 이동·확대해 선택합니다.
  4. 1278×852, 품질 0.85의 JPEG data URL로 변환합니다.
  5. 원본 파일 SHA-256 해시가 가능하면 기존 그림 캐시 조회에 사용합니다.
- **예외 흐름:** 형식·용량·크기·디코딩·Canvas 오류를 토스트로 알립니다. 같은 사진의 그림이 진행 중이면 안내합니다. 기존 그림이 있으면 재사용 또는 재생성을 선택합니다.
- **출력:** `photoDataUrl`, 선택적으로 `sourceHash`와 재사용할 `sketchDataUrl`
- **권한:** 파일 선택기 접근만 사용
- **관련 화면:** 업로드, 사진 영역 선택 모달
- **관련 API:** 없음
- **관련 데이터:** `DiaryDraft.photoDataUrl`, 그림 캐시와 원본 파일 해시
- **완료 조건:** 업로드 화면에 잘린 사진 미리보기가 표시됨
- **상태:** `구현 완료`
- **근거:** `src/components/PhotoUploadStep.tsx`, `src/components/PhotoCropModal.tsx`, `src/utils/image.ts`, `src/services/sketchCache.ts`

## F-04 일기 작성과 작업 사본 저장

- **목적:** 사진에 연결할 제목·날짜·날씨·본문을 수집하고 입력 중 손실을 줄입니다.
- **Actor:** 사용자
- **사전 조건:** 유효한 사진이 선택됨
- **입력:** 제목 0~~15자, 날짜, 5개 날씨 중 하나, 본문 0~~65자
- **정상 흐름:** 입력마다 공통 `DiaryDraft`를 갱신하고 400ms 뒤 `localStorage`에 저장합니다. 페이지 숨김·종료 시 즉시 저장을 시도합니다.
- **예외 흐름:** 공백뿐인 제목이나 본문은 검사 단계 진입을 막고 도움말 또는 토스트를 표시합니다. 저장 용량이 부족하면 그림, 사진 순서로 제외해 텍스트 저장을 재시도합니다.
- **출력:** 갱신된 `DiaryDraft`
- **권한:** 없음
- **관련 화면:** 작성
- **관련 API:** 없음
- **관련 데이터:** `summer-vacation-diary:draft:v2`
- **완료 조건:** 제목과 본문이 각각 공백이 아니면 `검사 받기`가 유효해짐
- **상태:** `구현 완료`
- **근거:** `src/components/WriteStep.tsx`, `src/App.tsx`, `src/hooks/useDiaryDraft.ts`, `src/constants/diary.ts`

> 앱은 `restoreOnStart: false`로 훅을 호출하므로 다음 방문에서 작업 사본을 자동 복원하지는 않습니다. 저장 로직은 같은 실행 중 페이지 이탈에 대비해 유지됩니다.

## F-05 사진 그림 변환

- **목적:** 선택한 사진을 그림일기용 크레파스/연필풍 이미지로 준비합니다.
- **Actor:** 사용자
- **사전 조건:** 사진이 있고 업로드 단계를 떠났으며 해당 작업이 지역·사용량 선검사에서 허용됨
- **입력:** 잘린 사진 data URL
- **정상 흐름:** 검사 받기 후 실제 모드는 필요한 분석과 함께 `inspect` action으로 요청하고, 체험 모드는 Canvas 연필 필터를 적용합니다. 테스트 모드는 원본을 그대로 사용합니다.
- **예외 흐름:** 실패하면 미리보기에서 원본 사진과 원인을 표시하고 재시도 가능한 오류에만 버튼을 제공합니다. 자동 재시도하지 않습니다.
- **출력:** 재압축한 JPEG `sketchDataUrl` 또는 원본 사진 대체 표시
- **권한:** 없음
- **관련 화면:** 작성 중 백그라운드 처리, 미리보기
- **관련 API:** `diary-ai`의 `inspect`
- **관련 데이터:** `DiaryDraft.sketchDataUrl`, 사진별 메모리 캐시, 요청 ledger
- **완료 조건:** 그림 data URL 저장 또는 명시적인 실패·원본 대체 상태 표시
- **상태:** `구현 완료`
- **구성:** 실제 모드는 배포된 Edge Function에 의존하고, 설정이 없으면 로컬 필터를 사용함
- **근거:** `src/hooks/useSketch.ts`, `src/services/styleTransfer.ts`, `src/utils/sketchFilter.ts`, `src/services/sketchCache.ts`, `src/services/sketchLedger.ts`

## F-06 일기 검사

- **목적:** 사진과 본문에서 키워드·감정·첨삭·선생님 한마디·도장을 생성합니다.
- **Actor:** 사용자
- **사전 조건:** F-04 완료 조건 충족
- **입력:** 사진 data URL 또는 `null`, 본문
- **정상 흐름:** `검사 받기`를 누르면 실제 모드에서 필요한 그림 변환과 함께 `inspect` action으로 요청하고, 체험 모드에서 결정적 예시 결과를 만듭니다. 입력 서명별 캐시와 동일 진행 Promise를 재사용합니다.
- **예외 흐름:** 시간 초과, 네트워크, 키, 지역, 사용량, 응답 형식 오류를 사용자 메시지로 변환합니다. 이전 입력의 늦은 응답은 현재 화면을 덮지 않습니다. 본문에 실제로 없는 첨삭 대상과 비속어가 포함된 대상은 버립니다.
- **출력:** 사진·일기 키워드, 감정, 동그라미 단어, 밑줄 문장, 별표 단어, 50자 이내 한마디, 도장 종류
- **권한:** 없음
- **관련 화면:** 작성, 미리보기
- **관련 API:** `diary-ai`의 `inspect`
- **관련 데이터:** 컴포넌트 생명주기 안 최근 결과 최대 3개
- **완료 조건:** 검증된 분석 결과 또는 재시도 가능 여부가 포함된 오류 상태
- **상태:** `구현 완료`
- **구성:** 실제 모드는 배포된 Edge Function에 의존하고, 설정이 없으면 결정적 mock을 사용함
- **근거:** `src/hooks/useDiaryAnalysis.ts`, `src/services/diaryAnalysis.ts`, `src/utils/profanity.ts`

## F-07 그림일기 미리보기

- **목적:** 완성 전 사진·일기·첨삭·한마디·도장을 한 장의 그림일기 형태로 확인합니다.
- **Actor:** 사용자
- **사전 조건:** F-04 완료 조건 충족
- **입력:** `DiaryDraft`, 그림 상태, 분석 상태
- **정상 흐름:** 1080×1350 프레임 좌표를 비율로 변환해 13×5 원고지, 사진, 날짜·날씨, 제목, 첨삭, 한마디와 도장을 렌더링합니다.
- **예외 흐름:** 그림 변환 실패 시 원본 사진, 분석 미실행·실패 시 한마디와 첨삭 없는 상태를 표시합니다. 재시도 가능한 오류만 재시도할 수 있습니다.
- **출력:** 화면 미리보기와 접근성 상태 메시지
- **권한:** 없음
- **관련 화면:** 미리보기
- **관련 API:** F-05, F-06 결과 사용
- **관련 데이터:** React 상태
- **완료 조건:** 현재 입력으로 그림일기 카드가 렌더링됨
- **상태:** `구현 완료`
- **근거:** `src/components/PreviewStep.tsx`, `src/components/DiaryFrameBackground.tsx`, `src/utils/diaryFrameLayout.ts`, `src/utils/highlight.ts`

## F-08 JPEG 완성·저장

> 완료 인지 UX의 상세 동작과 수용 기준은 [최종 완료 인지 강화 명세](./completion-feedback-specification.md)를 따릅니다.

- **목적:** 화면의 그림일기를 재사용 가능한 JPEG 파일로 만들고 기기에 저장합니다.
- **Actor:** 사용자
- **사전 조건:** 미리보기 진입, 사진 존재
- **입력:** `일기 완성하기`, 이후 `이미지 저장하기`
- **정상 흐름:** 합성 중에는 CTA에 `완성 중…`과 busy 상태를 표시합니다. Canvas에서 1080×1350 JPEG를 합성하면 체크 배지와 1회성 완료 모션이 있는 모달에 같은 data URL을 표시합니다. 토스·샌드박스에서는 `saveBase64Data`, 브라우저에서는 `<a download>`를 사용합니다.
- **예외 흐름:** 그림이나 분석이 진행 중이면 현재 상태로 저장할지 확인합니다. 분석 오류는 재시도 또는 그대로 저장을 선택합니다. 합성·저장 실패는 재시도 가능한 메시지를 표시합니다.
- **출력:** `summer-diary-YYYY-MM-DD-HHMMSS.jpg`
- **권한:** `granite.config.ts` 권한 배열은 비어 있음. 저장은 런타임 API 또는 브라우저 다운로드 사용
- **관련 화면:** 미리보기, 완성 모달
- **관련 API:** Apps in Toss `saveBase64Data`
- **관련 데이터:** 완성 이미지는 React 메모리에 머물고 저장 요청 시 기기로 전달됨
- **완료 조건:** 저장 API 완료 또는 브라우저 다운로드 시작
- **상태:** `구현 완료`
- **근거:** `src/App.tsx`, `src/utils/diaryImage.ts`, `src/services/diaryExport.ts`, `src/components/DiaryShareModal.tsx`

## F-09 앱 링크 공유

- **목적:** 완성 이미지를 업로드하지 않고 앱 소개와 진입 링크를 공유합니다.
- **Actor:** 사용자
- **사전 조건:** 완성 모달 열림
- **입력:** `앱 공유하기`
- **정상 흐름:** 토스에서는 `intoss://summer-vacation-diary`의 공유 링크를 생성해 Toss 공유창을 엽니다. 브라우저에서는 Web Share를 사용하고, 미지원 시 현재 URL을 클립보드에 복사합니다.
- **예외 흐름:** 사용자가 공유창을 취소하면 오류로 처리하지 않습니다. 링크 생성·공유창·복사 실패는 모달에 메시지를 표시합니다.
- **출력:** 앱 소개 문구와 앱 링크
- **권한:** 없음
- **관련 화면:** 완성 모달
- **관련 API:** `getTossShareLink`, `share`, `navigator.share`, Clipboard API
- **관련 데이터:** 완성 이미지 파일은 공유 payload에 포함하지 않음
- **완료 조건:** 공유창이 열리거나 링크가 복사됨
- **상태:** `구현 완료`
- **근거:** `src/services/diaryShare.ts`, `src/components/DiaryShareModal.tsx`

## F-10 사용량 안내·차단

- **목적:** 그림 생성과 분석을 하나로 묶은 AI 검사 사용량과 지역 제한을 사용자에게 알리고 불필요한 요청을 줄입니다.
- **Actor:** 사용자
- **사전 조건:** Supabase가 설정되고 클라이언트 테스트 모드가 꺼짐
- **입력:** 앱 시작의 `quota-status` 및 각 응답에 포함된 `quota`
- **정상 흐름:** 서버가 반환한 공통 `all` 카운터를 통합 AI 검사 기회로 표시합니다. 사진 변환이나 분석 중 하나만 다시 실행되어도 서버가 `all`을 원자적으로 1회 차감하며, 통합 기회를 모두 사용하면 두 작업을 함께 선차단합니다. `all`이 없는 이전 서버에서는 그림·분석 카운터 중 큰 사용량과 작은 한도를 배포 호환 fallback으로 사용하고, 그림 진행 중 요청은 로컬 ledger로 선반영합니다.
- **예외 흐름:** 조회 실패 시 사용량 UI를 `unknown`으로 두되 일기 흐름을 차단하지 않습니다. 해외 지역이면 실제 서버 작업을 선차단하고 원본 사진 흐름은 유지합니다.
- **출력:** 통합 AI 검사 사용량 안내, 두 작업의 공동 선차단, 오류 문구
- **권한:** 사용자 인증 없음. 익명 Toss 키 또는 브라우저 설치 ID를 `x-diary-client-id`로 보냄
- **관련 화면:** 업로드·작성 안내, 지역 차단 다이얼로그
- **관련 API:** `diary-ai`의 `quota-status`, `inspect`
- **관련 데이터:** `summer-vacation-diary:quota:v1`, `summer-vacation-diary:client-id:v1`, Supabase `public.diary_ai_rate_limits`
- **완료 조건:** 유효한 snapshot을 표시하거나 확인 불가 상태에서 기능을 안전하게 계속함
- **상태:** `구현 완료`
- **근거:** `src/hooks/useAiQuota.ts`, `src/services/aiQuotaStore.ts`, `src/services/supabaseEdge.ts`, `src/components/AiQuotaNotice.tsx`

## F-11 새 일기 시작

- **목적:** 완성 후 현재 입력을 지우고 새 제작 흐름으로 돌아갑니다.
- **Actor:** 사용자
- **사전 조건:** 완성 모달 열림
- **입력:** `새 일기 쓰기`
- **정상 흐름:** 완성 이미지를 닫고 draft storage와 React 입력 상태를 초기화한 뒤 업로드 단계로 이동합니다.
- **예외 흐름:** `localStorage.removeItem`이 실패해도 현재 화면 상태는 초기화합니다.
- **출력:** 빈 업로드 화면
- **권한:** 없음
- **관련 화면:** 완성 모달, 업로드
- **관련 API:** 없음
- **관련 데이터:** `summer-vacation-diary:draft:v2` 삭제 시도
- **완료 조건:** 사진·그림·제목·본문이 초기화됨
- **상태:** `구현 완료`
- **근거:** `src/App.tsx`, `src/hooks/useDiaryDraft.ts`

## 수동 회귀 확인

자동 테스트 프레임워크가 없으므로 변경 영향에 맞춰 다음을 확인합니다.

- [ ] 동의하지 않으면 최초 사진 선택이 시작되지 않는다.
- [ ] 지원하지 않는 형식, 10MB 초과, 가로·세로 중 하나가 200px 미만인 사진이 거부된다.
- [ ] 자르기 결과가 3:2이며 사진 교체 시 이전 그림이 새 사진에 남지 않는다.
- [ ] 제목 15자, 본문 20~65자와 공백 검사가 적용된다.
- [ ] 제목·날짜·날씨만 수정하면 분석 결과가 유지되고 검사 기회가 줄지 않는다.
- [ ] Supabase 미설정·테스트 모드·실제 모드의 사진 처리와 안내 문구가 일치한다.
- [ ] `quota.all` 한도가 3이면 하나의 AI 검사 기회 `3회`로 표시된다.
- [ ] `quota.all`이 없으면 두 action의 큰 사용량과 작은 한도를 fallback으로 표시한다.
- [ ] 통합 잔여량이 0일 때 사진 변환과 분석을 모두 선차단한다.
- [ ] 그림·분석 실패 시 원본으로 완성하거나 명시적으로 재시도할 수 있다.
- [ ] 미리보기와 저장 JPEG의 날짜·날씨·제목·본문·첨삭·도장이 일치한다.
- [ ] 합성 중 `완성 중…`이 표시되고, 합성 성공 후 완료 배지 모션이 한 번만 재생된다.
- [ ] 모션 감소 설정과 320×600 화면에서도 완료 문구와 모든 액션을 사용할 수 있다.
- [ ] 토스 WebView와 브라우저에서 저장·공유 대체 경로가 동작한다.
- [ ] `새 일기 쓰기`가 현재 입력과 완성 모달을 초기화한다.
