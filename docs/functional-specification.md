[README로 돌아가기](../README.md) · [정보구조](./information-architecture.md) · [API 명세](./api-specification.md) · [아키텍처](./architecture.md)

## 범위와 상태 기준

이 문서는 현재 저장소의 React 실행 경로를 기준으로 사용자가 조작할 수 있는 기능을 명세합니다.

- `구현 완료`: UI부터 결과 또는 오류 처리까지 실행 경로가 있음
- `부분 구현`: 핵심 흐름 일부만 있거나 저장소 밖 구성에 의존함
- `확인 필요`: 저장소 코드만으로 상태를 확정할 수 없음

주 Actor는 로그인 없이 미니앱 또는 모바일 브라우저를 사용하는 `사용자`입니다. 별도의 관리자·회원 역할은 없습니다.

대표 동작 화면은 [README 화면 갤러리](../README.md#동작-화면)와 [정보구조의 캡처 대응표](./information-architecture.md#현재-화면-캡처-대응표)에서 확인할 수 있습니다. 문서의 기능 ID와 화면 캡처는 현재 `App.tsx`의 3단계 제작 흐름 및 `calendar` 독립 목적지를 기준으로 연결합니다.

## F-01 온보딩 시작

- **목적:** 제품 이름과 여름 테마를 보여주고 제작 흐름에 진입시킵니다.
- **Actor:** 사용자
- **사전 조건:** 앱이 로드됨
- **입력:** `시작하기` 버튼 탭
- **정상 흐름:** 온보딩을 닫고 사진 업로드 1단계로 이동합니다.
- **예외 흐름:** 없음
- **출력:** 업로드 화면
- **권한:** 없음
- **관련 화면:** 온보딩, 업로드
- **관련 API:** 앱 로드 시 `quota-status`를 비차감 조회할 수 있음(F-10)
- **관련 데이터:** 온보딩 표시 여부는 React 메모리 상태이며 영구 저장하지 않음
- **완료 조건:** 업로드 화면과 1/3 진행 상태가 표시됨
- **상태:** `구현 완료`
- **근거:** `src/App.tsx`, `src/hooks/useAiQuota.ts`

## F-02 사진 처리 동의

- **목적:** 사진·일기와 남용 방지용 식별 정보의 처리 범위를 사진 선택 전에 알립니다.
- **Actor:** 사용자
- **사전 조건:** 현재 미니앱 실행 세션에서 아직 동의하지 않은 업로드 화면
- **입력:** `여름 사진 올리기`, 필수 체크박스, `동의하고 사진 선택`
- **정상 흐름:** 동의 내용을 확인하고 체크한 뒤 운영체제 파일 선택기를 엽니다.
- **예외 흐름:** 체크하지 않고 진행하면 체크 영역으로 이동하고 토스트를 표시합니다. 닫으면 사진 선택이 시작되지 않습니다.
- **출력:** 파일 선택기
- **권한:** Granite 권한 없음. HTML 파일 입력을 사용합니다.
- **관련 화면:** 업로드 화면의 `사진·일기 처리 동의` 모달
- **관련 API:** 없음
- **관련 데이터:** 동의 여부는 `App`의 React 메모리에만 유지하며 별도 동의 이력을 저장하지 않음
- **완료 조건:** 동의 후 파일 선택기가 열리고, 같은 실행 세션의 사진 교체·새 일기에서는 동의 모달을 생략함
- **상태:** `구현 완료`
- **근거:** `src/components/PhotoUploadStep.tsx`, `granite.config.ts`

## F-03 사진 선택·검증·자르기

- **목적:** 그림일기에 사용할 사진 한 장을 유효한 크기와 고정 비율로 준비합니다.
- **Actor:** 사용자
- **사전 조건:** 현재 실행 세션의 최초 선택은 F-02 동의 완료, 이후 선택은 세션 동의 유지
- **입력:** JPEG/JPG·PNG·WEBP 파일 1장, 자르기 위치, 1~3배 확대값, 90° 단위 회전값
- **정상 흐름:**
  1. MIME과 10MB 제한을 검사합니다.
  2. 이미지를 디코딩하고 가로·세로가 각각 200px 이상인지 검사합니다.
  3. 원본 비율과 관계없이 사진이 3:2 선택 영역을 빈틈없이 채우도록 `cover`로 표시합니다.
  4. 사용자가 3:2 영역을 이동·확대하거나 90°씩 회전해 선택합니다.
  5. 선택 좌표와 회전을 원본 픽셀에 적용해 1278×852, 품질 0.85의 JPEG data URL로 변환합니다.
  6. 원본 파일 SHA-256 해시가 가능하면 기존 그림 캐시 조회에 사용합니다.
- **예외 흐름:** 형식·용량·크기·디코딩·Canvas 오류를 토스트로 알립니다. 같은 사진의 그림이 진행 중이면 안내합니다. 기존 그림이 있으면 재사용 또는 재생성을 선택합니다.
- **출력:** `photoDataUrl`, 선택적으로 `sourceHash`와 재사용할 `sketchDataUrl`
- **권한:** 파일 선택기 접근만 사용
- **관련 화면:** 업로드, 사진 영역 선택 모달
- **관련 API:** 없음
- **관련 데이터:** `DiaryDraft.photoDataUrl`, 그림 캐시와 원본 파일 해시
- **완료 조건:** 업로드 화면에 잘린 사진 미리보기가 표시됨
- **상태:** `구현 완료`
- **근거:** `src/components/PhotoUploadStep.tsx`, `src/components/PhotoCropModal.tsx`, `src/utils/image.ts`, `src/services/sketchCache.ts`

## F-04 일기 작성과 작업 사본 저장

- **목적:** 사진에 연결할 제목·날짜·날씨·본문을 수집하고 입력 중 손실을 줄입니다.
- **Actor:** 사용자
- **사전 조건:** 유효한 사진이 선택됨
- **입력:** 제목 0~~15자, 오늘 이하의 날짜, 6개 날씨 중 하나, 낮·밤 배경, 본문 0~~65자
- **정상 흐름:** 입력마다 초안 고유 ID를 포함한 공통 `DiaryDraft`를 갱신하고 400ms 뒤 `localStorage`에 저장합니다. 페이지 숨김·종료 시 즉시 저장을 시도합니다. 날짜 입력기는 기기 현지 오늘 날짜를 `max`로 사용합니다.
- **예외 흐름:** 공백뿐인 제목이나 본문은 검사 단계 진입을 막고 도움말 또는 토스트를 표시합니다. 날짜 선택기를 처음 열면 오늘까지만 작성할 수 있다는 토스트를 표시하고, WebView나 저장값에서 미래 날짜가 들어오면 오늘로 보정합니다. 저장 용량이 부족하면 그림, 사진 순서로 제외해 텍스트 저장을 재시도합니다.
- **출력:** 갱신된 `DiaryDraft`
- **권한:** 없음
- **관련 화면:** 작성
- **관련 API:** 없음
- **관련 데이터:** `summer-vacation-diary:draft:v2`의 `draftId`, 사진, 그림, 제목, 본문, 날짜, 날씨, `timeOfDay`
- **완료 조건:** 제목과 본문이 각각 공백이 아니면 `검사 받기`가 유효해짐
- **상태:** `구현 완료`
- **근거:** `src/components/WriteStep.tsx`, `src/App.tsx`, `src/hooks/useDiaryDraft.ts`, `src/constants/diary.ts`

> 앱은 `restoreOnStart: false`로 훅을 호출하므로 다음 방문에서 작업 사본을 자동 복원하지는 않습니다. 저장 로직은 같은 실행 중 페이지 이탈에 대비해 유지됩니다.

## F-05 사진 그림 변환

- **목적:** 선택한 사진을 그림일기용 크레파스/연필풍 이미지로 준비합니다.
- **Actor:** 사용자
- **사전 조건:** 사진이 있고 업로드 단계를 떠났으며 해당 작업이 지역·사용량 선검사에서 허용됨
- **입력:** 잘린 사진 data URL
- **정상 흐름:** 검사 받기 후 실제 모드는 필요한 분석과 함께 `inspect` action으로 요청하고, 체험 모드는 Canvas 연필 필터를 적용합니다. 테스트 모드는 원본을 그대로 사용합니다.
- **예외 흐름:** 실패하면 미리보기에서 원본 사진과 원인을 표시하고 재시도 가능한 오류에만 버튼을 제공합니다. 자동 재시도하지 않습니다.
- **출력:** 재압축한 JPEG `sketchDataUrl` 또는 원본 사진 대체 표시
- **권한:** 없음
- **관련 화면:** 작성 중 백그라운드 처리, 미리보기
- **관련 API:** `diary-ai`의 `inspect`
- **관련 데이터:** `DiaryDraft.sketchDataUrl`, 사진별 메모리 캐시, 요청 ledger
- **완료 조건:** 그림 data URL 저장 또는 명시적인 실패·원본 대체 상태 표시
- **상태:** `구현 완료`
- **구성:** 실제 모드는 배포된 Edge Function에 의존하고, 설정이 없으면 로컬 필터를 사용함
- **근거:** `src/hooks/useSketch.ts`, `src/services/styleTransfer.ts`, `src/utils/sketchFilter.ts`, `src/services/sketchCache.ts`, `src/services/sketchLedger.ts`

## F-06 일기 검사

- **목적:** 사진과 본문에서 키워드·감정·첨삭·선생님 한마디·도장을 생성합니다.
- **Actor:** 사용자
- **사전 조건:** F-04 완료 조건 충족
- **입력:** 사진 data URL 또는 `null`, 본문
- **정상 흐름:** `검사 받기`를 누르면 실제 모드에서 필요한 그림 변환과 함께 `inspect` action으로 요청하고, 체험 모드에서 결정적 예시 결과를 만듭니다. 입력 서명별 캐시와 동일 진행 Promise를 재사용합니다.
- **예외 흐름:** 시간 초과, 네트워크, 키, 지역, 사용량, 응답 형식 오류를 사용자 메시지로 변환합니다. 이전 입력의 늦은 응답은 현재 화면을 덮지 않습니다. 본문에 실제로 없는 첨삭 대상과 비속어가 포함된 대상은 버립니다.
- **출력:** 사진·일기 키워드, 감정, 동그라미 단어, 밑줄 문장, 별표 단어, 50자 이내 한마디, 도장 종류
- **권한:** 없음
- **관련 화면:** 작성, 미리보기
- **관련 API:** `diary-ai`의 `inspect`
- **관련 데이터:** 컴포넌트 생명주기 안 최근 결과 최대 3개
- **완료 조건:** 검증된 분석 결과 또는 재시도 가능 여부가 포함된 오류 상태
- **상태:** `구현 완료`
- **구성:** 실제 모드는 배포된 Edge Function에 의존하고, 설정이 없으면 결정적 mock을 사용함
- **근거:** `src/hooks/useDiaryAnalysis.ts`, `src/services/diaryAnalysis.ts`, `src/utils/profanity.ts`

## F-07 그림일기 미리보기

- **목적:** 완성 전 사진·일기·첨삭·한마디·도장을 한 장의 그림일기 형태로 확인합니다.
- **Actor:** 사용자
- **사전 조건:** F-04 완료 조건 충족
- **입력:** `DiaryDraft`, 그림 상태, 분석 상태
- **정상 흐름:** 실제 그림·검사 작업이 있으면 3단계 처리 애니메이션을 표시합니다. 하단의 `일기 수정`과 `일기 완성하기`는 화면에 유지하되 카드·첨삭·도장 공개 애니메이션이 끝날 때까지 비활성화합니다. 완료 후 1080×1350 프레임 좌표를 비율로 변환해 13×5 원고지, 사진, 날짜·날씨, 제목, 첨삭, 한마디와 도장을 렌더링합니다. 처리 애니메이션이 끝난 미리보기 카드 위에만 `일기 완성하기`를 눌러야 달력에 저장된다는 안내를 표시합니다. 동작 줄이기 설정에서는 공개 애니메이션을 기다리지 않고 잠금을 해제합니다.
- **예외 흐름:** 사용량 소진으로 실행할 그림·검사 작업이 없으면 처리 애니메이션 없이 원본 기반 미리보기를 즉시 표시합니다. 그림 변환 실패 시 원본 사진, 분석 미실행·실패 시 한마디와 첨삭 없는 상태를 표시합니다. 현재 오류가 있을 때만 오류 모달을 열고, 결과가 정상 상태로 회복되면 모달을 닫습니다. 재시도 가능한 오류만 재시도할 수 있습니다.
- **출력:** 화면 미리보기와 접근성 상태 메시지
- **권한:** 없음
- **관련 화면:** 미리보기
- **관련 API:** F-05, F-06 결과 사용
- **관련 데이터:** React 상태
- **완료 조건:** 현재 입력으로 그림일기 카드가 렌더링됨
- **상태:** `구현 완료`
- **근거:** `src/components/PreviewStep.tsx`, `src/components/DiaryFrameBackground.tsx`, `src/utils/diaryFrameLayout.ts`, `src/utils/highlight.ts`

## F-08 JPEG 완성·저장

> 완료 인지 UX의 상세 동작과 수용 기준은 [최종 완료 인지 강화 명세](./completion-feedback-specification.md)를 따릅니다.

- **목적:** 화면의 그림일기를 재사용 가능한 JPEG 파일로 만들고 기기에 저장합니다.
- **Actor:** 사용자
- **사전 조건:** 미리보기 진입, 사진 존재
- **입력:** `일기 완성하기`, 이후 `이미지 저장하기`

- **예외 흐름:** 조회 실패 시 사용량 UI를 `unknown`으로 두되 일기 흐름을 차단하지 않습니다. 해외 지역이면 실제 서버 작업을 선차단하고 원본 사진 흐름은 유지합니다.
- **출력:** 통합 AI 검사 사용량 안내, 두 작업의 공동 선차단, 오류 문구

## F-12 완성 일기 자동 보관

- **목적:** 완성한 일기를 기기에 자동 보관해 일기 달력에서 다시 열 수 있게 합니다.
- **Actor:** 사용자
- **사전 조건:** F-08의 Canvas 합성 성공
- **입력:** 합성된 JPEG, 초안 ID, 사진·본문 revision hash와 현재 날짜·제목·날씨·AI 생성 여부
- **정상 흐름:** JPEG와 초안 ID, AI 입력인 사진·본문의 revision hash를 `saveDiary`에 전달합니다. 전체 기록을 일기별 key에 먼저 쓰고 이미지가 없는 요약 index를 나중에 갱신합니다. 저장에 성공하면 `일기가 달력에 저장되었어요! (현재 개수/3)` 토스트를 한 번 표시하고 저장 날짜의 달력으로 이동합니다. 해당 날짜에 도장이 찍히는 애니메이션을 보여주고 1.5초 뒤 방금 저장한 기록을 자동으로 엽니다. 같은 초안의 revision hash가 유지되면 날짜·제목·날씨 변경을 기존 기록에 반영하고, 사진 또는 본문이 바뀌면 새 ID의 별도 기록으로 저장합니다.
- **호환 흐름:** `revisionKey`가 없는 이전 버전 기록은 사진 일치 여부를 확정할 수 없어 다른 날짜 기록과 자동 병합하지 않고 보존합니다. 같은 날짜의 동일 완성 이미지를 다시 저장할 때만 새 형식으로 교체합니다.
- **예외 흐름:** 같은 날짜에 서로 다른 일기가 3개면 날짜 선택 단계에서 기존 기록을 삭제할 수 있는 달력 상세 이동을 안내합니다. 저장 시점에도 `daily-limit`으로 다시 검증하며, 저장 공간 부족은 `storage-full`, 읽기 실패는 `read-failed`로 처리해 토스트를 표시하고 미리보기를 유지합니다.
- **출력:** 저장된 `DiaryRecord`, 저장 성공 토스트
- **권한:** `granite.config.ts` 권한 배열은 비어 있음
- **관련 화면:** 미리보기, 일기 달력, 일기 뷰어
- **관련 API:** Apps in Toss `Storage`(브라우저 개발 환경에서는 localStorage 대체)
- **관련 데이터:** `summer-vacation-diary:diary-index:v1`, `summer-vacation-diary:diary:v1:<id>`
- **완료 조건:** 일기 달력 index와 일기 항목이 기기 저장소에 반영됨
- **상태:** `구현 완료`
- **근거:** `src/App.tsx`, `src/services/diaryStore.ts`

## F-13 일기 달력 열람·공유·삭제

- **목적:** 기기에 보관한 완성 일기를 월·날짜별로 다시 보고 관리합니다.
- **Actor:** 사용자
- **사전 조건:** 온보딩 종료
- **입력:** `나의 기록 보기`, 이전·다음 달, 도장이 있는 날짜, 뷰어 이동·스와이프, `저장 및 공유`, `일기 삭제`
- **정상 흐름:** 현재 달을 월요일 시작 달력으로 표시하고 기록이 있는 날짜에 완료 도장을 표시합니다. 완성 직후 진입하면 저장 날짜가 포함된 달에서 새 도장 애니메이션을 먼저 재생하고 1.5초 뒤 방금 저장한 일기를 엽니다. 날짜를 직접 누르면 해당 날짜 셀에 강조 링을 표시한 뒤 종이 조각이 날짜 위치에서 천천히 확대되어 상세 카드로 펼쳐지며 그 날 일기를 최신순으로 엽니다. 같은 날 여러 일기는 화살표나 48px 이상 좌우 스와이프로 이동합니다. `저장 및 공유`는 저장·공유 모달을 열어 이미지 저장 또는 앱 링크 공유를 제공합니다. 날짜 관리로 진입한 상세에서는 공유를 숨기고 삭제에 집중합니다. 삭제는 확인 모달 이후 index와 항목을 제거합니다. 달력의 `돌아가기`는 완성 후에는 그림 선택 화면으로, 날짜 관리 후에는 일기 쓰기 화면으로 이동합니다.
- **예외 흐름:** 빈 달은 안내 문구를 표시합니다. 손상되거나 사라진 항목은 찾을 수 없음으로 표시하고 index를 정리합니다. 조회·공유·삭제 오류는 현재 화면을 유지한 채 알립니다.
- **출력:** 월별 완료 도장, 완성 JPEG 뷰어, 갱신된 보관 목록
- **권한:** 없음
- **관련 화면:** 업로드, 일기 달력, 일기 뷰어, 삭제 확인 모달
- **관련 API:** Apps in Toss `Storage`, `saveBase64Data`; 브라우저 localStorage·download
- **관련 데이터:** F-12의 index와 일기별 record
- **완료 조건:** 사용자가 저장한 일기를 열거나 공유·삭제 결과를 확인함
- **상태:** `구현 완료`
- **근거:** `src/components/DiaryCalendarView.tsx`, `src/services/diaryStore.ts`, `src/services/diaryExport.ts`, `src/utils/diaryCalendar.ts`

## 수동 회귀 확인

자동 테스트 프레임워크가 없으므로 변경 영향에 맞춰 다음을 확인합니다.

- [ ] 동의하지 않으면 최초 사진 선택이 시작되지 않는다.
- [ ] 지원하지 않는 형식, 10MB 초과, 가로·세로 중 하나가 200px 미만인 사진이 거부된다.
- [ ] 세로·가로 사진이 3:2 선택 영역을 가득 채우고, 이동·확대·90° 회전 결과가 1278×852 JPEG와 일치한다.
- [ ] 사진 교체 시 이전 그림이 새 사진에 남지 않는다.
- [ ] 제목 15자, 본문 65자·5줄 제한과 공백 검사가 적용된다.
- [ ] `모름`을 포함한 6개 날씨와 낮·밤 배경을 선택할 수 있다.
- [ ] 오늘 이후 날짜를 선택할 수 없고 미래 날짜 값은 오늘로 보정된다.
- [ ] 낮·밤과 날씨를 바꾸면 화면 배경이 갱신되고 AI 입력·검사 결과는 바뀌지 않는다.
- [ ] 제목·날짜·날씨만 수정하면 분석 결과가 유지되고 검사 기회가 줄지 않는다.
- [ ] Supabase 미설정·테스트 모드·실제 모드의 사진 처리와 안내 문구가 일치한다.
- [ ] `quota.all` 한도가 3이면 하나의 AI 검사 기회 `3회`로 표시된다.
- [ ] 통합 잔여량이 0일 때 사진 변환과 분석을 모두 선차단한다.
- [ ] 통합 잔여량이 0이면 3단계 처리 애니메이션 없이 미리보기가 즉시 표시된다.
- [ ] 그림·분석 실패 시 원본으로 완성하거나 명시적으로 재시도할 수 있다.
- [ ] 처리·공개 애니메이션 중 하단 버튼은 계속 보이지만 `일기 수정`과 `일기 완성하기`가 모두 비활성화되고, 도장 또는 카드 공개가 끝나면 활성화된다.
- [ ] 미리보기 카드 위에 완성 버튼을 눌러야 달력에 저장된다는 안내가 표시된다.
- [ ] 미리보기와 저장 JPEG의 날짜·날씨·제목·본문·첨삭·도장이 일치한다.
- [ ] 합성 중 `완성 중…`이 표시되고, 합성 성공 후 달력의 도장과 저장 일기 상세가 순서대로 열린다.
- [ ] 모션 감소 설정과 320×600 화면에서도 완료 문구와 모든 액션을 사용할 수 있다.
- [ ] 토스 WebView와 브라우저에서 저장·공유 대체 경로가 동작한다.
- [ ] 완성한 일기가 일기 달력의 해당 날짜에 자동 보관되고 같은 날 최대 3개까지만 저장된다.
- [ ] 달력 보관 성공 직후 `일기가 달력에 저장되었어요! (현재 개수/3)` 토스트가 한 번 표시된다.
- [ ] 달력 보관 성공 직후 저장 날짜에 새 도장이 찍힌 다음 방금 저장한 기록이 자동으로 열린다.
- [ ] 같은 초안의 사진·본문은 유지하고 날짜만 바꿔 재저장하면 이전 날짜 기록이 사라지고 새 날짜에 하나만 남는다.
- [ ] 같은 초안이라도 사진 또는 본문을 수정한 뒤 다른 날짜로 저장하면 두 날짜에 서로 다른 기록이 남는다.
- [ ] 같은 날짜의 여러 일기를 버튼과 좌우 스와이프로 이동할 수 있다.
- [ ] 보관 일기를 이미지로 내보내고 확인 후 삭제할 수 있다.
- [ ] 상세 뷰어의 `저장 및 공유`가 저장·공유 모달을 열고 `창 닫기`가 현재 상세를 유지한다.
- [ ] 달력의 `돌아가기`가 완성 후에는 그림 선택 화면으로, 날짜 관리 후에는 일기 쓰기 화면으로 이동한다.
