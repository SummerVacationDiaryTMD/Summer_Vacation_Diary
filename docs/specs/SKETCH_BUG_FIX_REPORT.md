# 그림 유실 버그 보고 (팀 공유용)

> **요약** — 사진을 바꿨다가 원래 사진으로 되돌아오면, 서버가 정상적으로 그려 준
> 그림을 앱이 "낡은 응답"으로 잘못 판단해 버리는 버그입니다. 그림은 사실 휴대폰
> 안까지 도착해 있는데 화면에는 "알 수 없는 이유로 그림을 못그렸어요."가 뜨고,
> 다시 시도 버튼도 없어 그대로 막힙니다. **서버는 아무 문제 없고, 앱 코드
> 한 파일(`src/hooks/useSketch.ts`)만 고치면 됩니다.**
>
> 구현 세부 명세: [`SKETCH_BUG_FIX_SPEC.md`](./SKETCH_BUG_FIX_SPEC.md) (영어)

## 1. 무슨 일이 생기나요?

이 순서대로 하면 항상 재현됩니다.

1. 사진 A를 올리고 **일기 쓰러 가기** → 그림 A 요청이 시작됩니다 (30~60초 소요).
2. 마음을 바꿔 **사진 변경**으로 사진 B를 올리고 다시 **일기 쓰러 가기** → 그림 B
   요청도 시작됩니다.
3. 다시 **사진 변경**으로 사진 A를 재선택합니다 (크롭은 조정 없이 그대로 확정).
4. **업로드 화면에 머무는 동안** 그림 A가 도착하면 → 그 그림은 영영 화면에
   반영되지 않습니다. 이후 미리보기에 "알 수 없는 이유로 그림을 못그렸어요."가
   뜨고, 다시 시도 버튼도 없습니다.

이상한 점: Supabase 로그를 보면 서버는 그림 A를 **정상적으로 그려서 응답까지
보냈습니다**. 실제로 그림 파일은 휴대폰 안(localStorage 캐시)에 저장까지 되어
있습니다. 앱이 받아 놓고 버린 것입니다.

## 2. 왜 이런 일이?

그림 요청마다 앱이 **접수번호**를 붙이는데, 이 번호가 사진별이 아니라 **전체
공용**입니다. "가장 최근 접수번호의 응답만 화면에 반영한다"는 규칙 때문에,
사진 B를 접수한 순간(번호 2) 사진 A의 응답(번호 1)은 무효 판정이 예약됩니다.

문제는 여기서 끝나지 않습니다. 그림 A가 도착하는 순간 앱의 **사용량 장부**에는
"사진 A는 그리기 완료"라고 먼저 적힙니다. 그래서:

- 화면 반영은 거부됐는데 (접수번호가 낡아서),
- 장부에는 "완료"라고 적혀 있어 **다시 요청하는 것도 금지**되고,
- "완료된 사진" 차단 검사가 **캐시 확인보다 먼저** 실행되는 바람에, 저장된
  그림을 꺼내 쓰는 길도 막힙니다.

장부 따로, 화면 따로가 된 채로 교착되는 것입니다. 3단계에서 "재요청을 안 하니
의도대로 동작한다"고 보였던 것도 사실은 중복 방지가 아니라 이 "완료" 기록이
막은 것이었습니다.

참고로 3단계에서 크롭을 그대로 확정하면 결과 이미지가 처음과 바이트 단위로
같아서 같은 사진으로 인식됩니다. 크롭을 손으로 조정하면 다른 사진 취급이라
이 버그 대신 다른 경로로 빠집니다.

## 3. 어떻게 고치나요?

두 가지를 고칩니다. 자세한 구현은 [`SKETCH_BUG_FIX_SPEC.md`](./SKETCH_BUG_FIX_SPEC.md) 참고.

1. **판정 기준을 사진 단위로** — "낡은 응답" 판정을 전체 공용 접수번호 대신
   "도착한 그림의 사진이 지금 사진이고, 아직 반영된 그림이 없는가"로 바꿉니다.
   요청 중복 방지가 이미 사진 단위로 되어 있으니 판정도 같은 기준이어야 합니다.
2. **캐시 확인을 차단 검사보다 먼저** — "완료된 사진" 차단보다 저장된 그림
   확인을 먼저 해서, 혹시 또 어긋나더라도 다음 화면 진입 때 저절로 복구되게
   합니다.

## 4. 지금 이 상태에 걸린 사용자는?

- **앱을 껐다 켜면 풀립니다.** "완료" 장부는 메모리에만 있어서 세션이 끝나면
  사라집니다.
- 앱을 켠 채로도, 같은 사진을 **한 번 더 선택**하면 "이미 그린 그림이 있어요"
  창이 떠서 그림을 되살릴 수 있습니다 (그림이 기기에 저장되어 있다는 증거이기도
  합니다).
- 서버 쪽 조치는 없습니다. Edge Function·SQL 재배포도 필요 없습니다.

## 5. 수정 확인 방법

| 시나리오                                                       | 기대 결과                                        |
| -------------------------------------------------------------- | ------------------------------------------------ |
| 위 1절의 재현 순서 그대로                                      | 그림 A가 미리보기에 정상 반영                    |
| A → B → A를 빠르게 오가기 (응답 도착 전)                       | 사진당 서버 요청 1건 유지 (중복 과금 없음)       |
| 그림 실패 후 화면 이동                                         | 자동 재시도 없음, 다시 시도 버튼으로만 재요청    |
| 오늘 횟수를 다 쓴 상태                                         | "횟수를 다 써서" 안내 그대로, 요청 없음          |

전체 검증 목록과 명령어는 명세서 6절에 있습니다.
